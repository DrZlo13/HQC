# T21: решения по ходу и открытые вопросы

Пять решений пользователя (зеркало по умолчанию, без дублей при включении, заголовки через
провайдера, отпечаток машины, уборка), SPEC 0.23. Живых прогонов `claude` не было: всё на
фикстурах, фейковом воркере, фейковом хабе и фейковых серверах моделей.

## Решения, принятые по ходу

- **`session.cleanup` — новый кадр, а не флаг у `session.kill`.** Кадр добавлен только
  добавлением; `session.kill` не менялся (его семантика — «убить процесс», уборка — другое
  действие, и `kill` уходит и тогда, когда процесса нет). В кадре кроме `{session_id,
  workspace_path, cwd}` из постановки есть `event_ids[]` — вводы сессии с вложениями: воркер сам не
  знает, какие папки `.hqc/inbox/<event_id>` принадлежат сессии (после перезапуска памяти нет), а
  удалять всю `.hqc/inbox` нельзя — в том же `cwd` работают другие сессии. Кадр шлётся при
  архивации, удалении сессии и удалении проекта (его сессии удаляются тоже); у сессии без вложений
  в workspace кадра нет. `workspace_path: null` — сессия без workspace, воркер удаляет
  `<scratch_root>/<session_id>`. Служебные сессии кадра не получают.
- **Воркер офлайн в момент архивации** — кадр не досылается (хаб его нигде не хранит); остаток
  убирает уборка при старте через 14 дней.
- **«Известные workspace» для уборки при старте** — `known_workspaces.json` плюс новый
  `$HQC_HOME/inbox_dirs.json`: рабочие каталоги, куда воркер писал вложения (сессии с `cwd` в
  подпапке держат inbox не в корне workspace, а обходить дерево workspace дорого). Каталог из
  `inbox_dirs.json` учитывается, только если лежит внутри workspace из `known_workspaces.json` и
  внутри `allowed_roots`. Удаляются только дети `.hqc/inbox` с именем-uuid (так их создаёт воркер),
  возраст — по времени изменения папки события. Пустые `.hqc/inbox` и `.hqc` остаются.
- **«Первый проход» зеркала** — первое чтение файла, который зеркало ещё не читало (смещение 0 в
  `mirror.sqlite3`), до конца файла. Повторный `mirror.set` после `hello` уже прочитанные файлы не
  трогает. `since_ts` — `max(ts)` всех событий сессии в хабе, включая события самого хаба.
- **`mirror.set.sessions`** — не больше 5000 самых свежих сессий workspace (кадр должен оставаться
  далеко от лимита сообщения WebSocket, §20); сессии без событий не перечисляются.
- **Заголовок из промпта ставится тоже с `title_source: runtime`** (иначе каждый следующий ответ
  запускал бы попытку снова). Попытка — одна на сессию за процесс хаба; после перезапуска хаба
  сессия, у которой заголовок остался `default` (нет промпта с текстом), получит ещё одну при
  следующем ответе. Вызовы модели — не больше 4 одновременно: импорт приносит десятки сессий разом.
  `ai-title`, пришедший позже, заменяет заголовок хаба по общему правилу `runtime`.
- **Обрезка до 60 символов по слову** — последний пробел до 59-го символа, хвостовые знаки
  препинания срезаются, затем «…»; одно длинное слово режется жёстко. Markdown убирается построчно:
  заголовки, цитаты, маркеры списков, `**`, `__`, обратные кавычки, ссылки `[текст](url)`; строка,
  начинающаяся с тройных кавычек, пропускается.
- **Провайдер `anthropic`**: `POST <база>/v1/messages`, `anthropic-version: 2023-06-01`, ключ в
  `x-api-key`; **`openai`**: `POST <база>/chat/completions`, ключ — `Authorization: Bearer`, без ключа
  заголовка нет. Редиректы не выполняются (ключ не уходит на другой хост).
- **Отпечаток машины** хаб принимает только как 64 шестнадцатеричных знака (в нижнем регистре);
  иное игнорирует молча. При замене отпечаток берётся из новой регистрации, если он есть.
- **Артефакты**: возраст считается по `updated_at`, который теперь обновляет повторная загрузка
  того же файла и ввод с ним, — иначе артефакт, загруженный 31 день назад и только что приложенный
  заново, мог бы исчезнуть между загрузкой и вводом.
- **Мок хаба клиента**: `mirror_enabled` по умолчанию `true`, но импорт фиктивных сессий — только при
  явном `mirror_enabled: true` (кнопка «Импорт из Claude Code»), чтобы не менять остальные
  сценарии.
- **SPEC §5.3 и §5.4** в этой версии не правились (там же меняет T22): кадр `session.cleanup`,
  `mirror.set.sessions` и `hello.machine_id` описаны в §17.4, §9.1 и §5.1. При слиянии добавить
  их в перечни кадров §5.3/§5.4.

## Открытые вопросы

1. **Массовый импорт после обновления.** Миграция `0011` включила зеркало у всех workspace: при
   первом `hello` после обновления воркер импортирует все прошлые транскрипты Claude Code в этих
   папках (каждый — отдельная сессия в проекте, у каждой — заголовок, с моделью — по вызову).
   Сессии hqc при этом не дублируются (`since_ts`). Нужно ли ограничение «импортировать только
   транскрипты моложе N дней» или подтверждение в клиенте?
   *Слияние с T22 (SPEC 0.24):* волна упирается в лимит T22 — 200 новых сессий за 24 ч на
   воркер; сверх него хаб отвечает `error mirror_quota` (retryable), воркер перечитывает
   транскрипт не чаще раза в час, так что импорт растягивается на дни, ничего не теряя. Вопрос о
   «моложе N дней» и подтверждении остаётся.
2. **Дубли после падения воркера** (вопрос 1 T15, вторая часть) остаются: реестр своих uuid в
   памяти, и записи адаптера, которые зеркало не успело пройти до падения, после перезапуска
   выглядят чужими. С зеркалом по умолчанию это касается всех workspace. Окно — до 2 с; можно
   хранить реестр на диске или применять `since_ts` и к первому проходу после перезапуска.
3. **`since_ts` по событиям хаба.** Если последнее событие сессии в хабе — системное, записанное
   позже записей VS Code (например, `turn_lost` при переподключении), эти записи при включении
   зеркала не придут. Можно брать `max(ts)` только событий воркера.
4. **Windows `MachineGuid` и Linux без `/etc/machine-id`** не проверены на живой машине; на
   home-mac `ioreg` работает (тест `this_machine_has_a_fingerprint`). Клонированные образы ВМ с
   одинаковым `machine-id` дадут одинаковый отпечаток — это лишь подсказка в клиенте.
5. **Заголовок без финального ответа.** Сессия, где агент не дал финального текста (ход упал),
   остаётся «Сессия N». Брать заголовок из промпта сразу при первом вводе?
6. **Квота на артефакты** (вопрос 5 T16) не делалась.
