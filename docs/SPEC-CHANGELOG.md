# hqc — история изменений ТЗ (старые версии)

Актуальные записи — в конце docs/SPEC.md.

### 0.3 → 0.4 (обзор аналогов)
ACP как общий адаптер вместо самописного `tui_gateway` для Hermes; MCP hqc через
`mcpServers` в `session/new`, что закрывает [проверить] из 0.3 (§8.2, §7);
рантайм `acp` с `acp_agent` (§3); Claude Code остаётся на нативном адаптере (§8.2);
`client_op_id` (§6); раздел аналогов и отвергнутая альтернатива без хаба (§22);
риск по ACP v2 (§21).

### 0.2 → 0.3 (по ревью 3 и 4)
Привязки «путь → окружение» и `allow_local_mcp` только в локальном конфиге воркера,
§2.1 приведён в соответствие (§14, §2.1); Hermes платит владелец воркера (§11.1);
зеркало не эмитит сессии, запущенные hqc, детерминированный `event_id` для зеркала
и импорта (§9.2, §3); детекция чужого писателя только по основной цепочке
user/assistant, предупреждение об устаревшем контексте VS Code (§9.3); `cwd` из
записей jsonl вместо декодирования имени папки, игнорирование транскриптов
субагентов (§9); `in_reply_to` на `agent.message`, ответ на ask по нему (§4, §7.1);
две очереди: ввод и буфер send, `peer_prefix` в `session.input` (§7.1, §5.3);
доставка hub → worker с `delivered_at` и ack, досылка после `hello`, очередь ввода
не хранится на воркере, смещения зеркала на диске (§5.2); подписанные ссылки
на публичный домен артефактов (§12, §20); `--strict-mcp-config` по умолчанию (§8.1);
приоритет состояний, `state` не хранится (§17.1, §3); `final` по следующему
элементу потока, `--replay-user-messages` (§8.1); `allow_foreign_sessions` и
`env_bindings` в `hello` (§5.4, §3); `dir` удаляется только записью (§13.2); строки
таблицы доступа: clarify, удалить проект, разархивировать, schedule, send/ask
(§11); подтверждение встроено в запрос владельца воркера, служебная сессия
перенесена в итерацию 2 (§10.2, §19); `locked_by` при импорте (§9.1); `chain`
текущего хода отдаётся MCP (§7.1); `always` → `session` в `--restricted` (§8.1);
API помечен как неполный, добавлены «позже» (§6); `reply_to` убран, `session`
у `hqc_send` необязателен, `content` у `hqc_attach` (§7); защита от подделки
заголовка peer (§4); ask в `locked_vscode` — ошибка, в `worker_offline` — ожидание,
грант `write` для send/ask (§7.1); `approval.cancel {worker_restart}` (§4, §17.3);
`worker_id` для любого рантайма без workspace (§3); рантайм ассистента меняется
в настройках (§8.3); push — владельцу и писавшим без активной подписки (§16);
ограничение стемминга (§15); предупреждение про `auto_approve` на расшаренном
проекте (§10.1); токен сессии: без файла конфига, без системного промпта,
ограничение видимости названо (§7, §8.2); формулировки: «Ограничение:», колонка
«владелец проекта», User без `owner_id`.

### 0.1 → 0.2 (по ревью 1 и 2)
Механизм разрешений Claude Code через `control_request`; `owner_id` у
Session/Workspace/Grant и правило «кто платит»; outbox, ack, `event_id`, `seq` от
хаба; семантика send/ask, заголовок peer-сообщений, `chain`; токен сессии для MCP;
подхват: `--resume` сохраняет uuid (проверено); окружения применимы к Hermes через
отдельный процесс `tui_gateway`; проверка JWT Access и разделение маршрутов;
модель угроз; таблица состояний; `approval.cancel`; очередь ввода; версия протокола
и формат фреймов; минимальный API клиента, `ReadCursor`; таблица уровней доступа;
правила удаления workspace и выбора workspace; `--restricted`; зеркало по пути;
slug адресов; крон с часовым поясом; поиск с грантами; лимит 100 МБ; изоляция HTML;
событие `usage`; служебная сессия воркера; личный проект для ассистента;
определения терминов.
