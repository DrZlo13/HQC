# Находки первого деплоя (2026-10-22, хаб ai.ebal.uk в Docker, воркер home-mac)

Сквозной сценарий §19.1 через Cloudflare Tunnel + Access прошёл: воркер online, сессия,
ввод, Bash, финальный ответ. Push и PWA с телефона ещё не проверены.

Мелкие баги, в итерацию 2:

1. **enroll и Keychain.** По ssh без разблокированной связки `enroll` получает токен от
   хаба и только потом падает на записи в Keychain («User interaction is not allowed»).
   Токен при этом сгорает, воркер на хабе остаётся без токена, его надо отзывать и
   регистрироваться заново. Нужно: проверять доступность хранилища до запроса токена
   (пробная запись), а при отказе подсказывать `security unlock-keychain` или
   `HQC_TOKEN_STORE=file`. Runbook §2.3 дополнить про ssh.
2. **DEBUG-логи reqwest/hyper в выводе enroll** при незаданном RUST_LOG: фильтр по
   умолчанию `info` в `enroll` не применяется (в `run` применяется).
3. **Ложное «hub dropped the event: unknown session»** на каждый `agent.delta`: хаб
   подтверждает дельты ack без `seq` (они не хранятся, §4), а воркер любой ack без `seq`
   считает отброшенным. Либо воркер не логирует это для дельт, либо хаб отвечает дельтам
   отдельным признаком.
4. **Имя воркера** берётся из hostname и получается `home-mac.tail201738.ts.net`; в
   `enroll` нужен флаг `--name`.

5. **Keychain и headless-запуски.** После первого запуска Claude Code из сессии с
   разблокированной связкой он переносит учётные данные из `~/.claude/.credentials.json`
   в Keychain и удаляет файл. В обычной ssh-сессии связка заперта, и любой headless
   `claude -p` (в том числе воркер, запущенный по ssh без `security unlock-keychain`)
   отвечает «Not logged in». Решение: запускать воркер и прочие headless-процессы в
   gui-домене launchd пользователя (RUNBOOK §2.4) или после `security unlock-keychain`
   в той же ssh-сессии. Записать в RUNBOOK §2.3/§2.4.
6. **`tools/e2e-local.sh` с `E2E_CLAUDE_BIN=/usr/bin/false`** доходит до живого хода и
   заканчивается FAIL по таймауту (три `agent_start_failed`, ввод `failed`). Это
   ожидаемо, но скрипту нужен явный режим репетиции, который на этом месте печатает PASS.
