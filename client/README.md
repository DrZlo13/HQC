# hqc client

Веб-клиент hqc (PWA): проекты и их сессии, workspace проекта (T14), чат сессии с карточками событий §4,
кнопки разрешений, регистрация воркера, Web Push. Задача T5 в `docs/ITERATION-1.md`,
протокол — `docs/SPEC.md` §4, §6, §10.1, §16, §17.1.

## Стек

TypeScript + Vite + Preact (без UI-библиотек, стили свои в `src/styles.css`), тесты на
vitest и happy-dom. Preact выбран как самый маленький компонентный рендерер с привычной
моделью JSX и хуков: весь клиент без markdown — около 18 КБ gzip, что важно для первого открытия с
телефона через туннель, а компоненты и хуки позволяют держать карточки событий
независимыми и тестировать их рендером в DOM. Чистый TypeScript без фреймворка потребовал
бы своего механизма перерисовки потока дельт и состояния кнопок, а React/Solid/Svelte не
дают здесь ничего нужного сверх Preact при большем весе или собственном компиляторе.
Markdown сообщений (T11) разбирает [marked](https://marked.js.org) только своим лексером
(`Lexer.lex`): он отдаёт токены, а элементы Preact из них строит `src/ui/Markdown.tsx`, так
что `innerHTML` нет нигде, а сырой HTML из текста остаётся текстом. marked выбран вместо
micromark + mdast-util-from-markdown потому, что это один файл без зависимостей и без DOM,
с GFM (таблицы, списки задач, автоссылки, зачёркивание) из коробки, и в нём нет `eval` и
`new Function`, то есть CSP §20 не мешает. Связка micromark даёт более строгий CommonMark,
но с GFM это 59 пакетов и 110 КБ (26 КБ gzip) без минификации в пробной сборке; marked —
47 КБ минифицированного кода, клиент вырос с 18,6 до 34,1 КБ gzip. Парсер и рендерер
marked в сборку тоже попадают (пакет — один файл, tree-shaking их не убирает); если вес
станет важен, лексер можно заменить, не трогая рендер.
Редизайн T26 добавил около 7,5 КБ gzip JS (44,5 → 52,1 КБ) и 3,6 КБ gzip CSS (4,2 → 7,7 КБ);
шрифты (≈180 КБ woff2) грузятся браузером по `unicode-range` и начертанию, только нужные.
Сервис-воркер (`public/sw.js`) написан на чистом JS без сборки: он маленький и отвечает
только за push.

## Скрипты

| команда | что делает |
|---|---|
| `npm run dev` | Vite dev-сервер на :5173, `/api` (REST и WebSocket) проксируется на `HQC_HUB_URL` (по умолчанию `http://127.0.0.1:8080`) |
| `npm run dev:mock` | мок-хаб (`mock/server.mjs`, :8787) и Vite dev-сервер с прокси на него, одним процессом |
| `npm run mock` | только мок-хаб, без Vite |
| `npm test` | все тесты: парсер по всем `examples/wire`, рендер карточек и markdown, сценарий на моке через транспорт клиента и через UI, прокси dev-сервера |
| `npm run test:scenario` | только сценарные тесты на моке |
| `npm run build` | `tsc --noEmit` и сборка в `dist/` |
| `npm run typecheck` | только проверка типов |
| `npm run icons` | перегенерировать PNG-иконки в `public/` |

## Структура

- `src/proto.ts` — типы и разбор событий §4, фреймов §5 и сообщений `/api/ws`; терпимость
  по §4 (неизвестный `type` → `UnknownEvent`, неизвестное значение перечисления →
  `"unknown"`, неверный payload известного типа → `ProtoError`).
- `src/api.ts` — REST §6; `src/ws.ts` — `/api/ws` с реконнектом и повтором `subscribe`
  от последнего `seq`; `src/timeline.ts` — что показывает чат (события по `seq`, поток
  `agent.delta`, оптимистичные сообщения по `client_op_id`, судьба запросов);
  `src/session.ts` — открытый чат: история по REST, хвост по WS, действия.
- `src/ui/` — интерфейс по макетам T26 (`docs/design/redesign-2026-10-24`, тёмная тема):
  - `App.tsx` — раскладка: на десктопе полоса проектов (`ProjectRail`), колонка сессий
    (`SessionList`) и экран; на телефоне (уже 900px, `useIsPhone`) один экран за раз;
  - `SessionList.tsx` + `sessions.ts` — колонка сессий: режимы «Состояние»/«Недавние» (выбор в
    `localStorage`, ключ `hqc.sessionOrder`), поиск по заголовку и пути, счётчики проекта,
    воркеры с числом активных сессий (клик — служебная сессия), форма новой сессии; на телефоне
    проекты чипами и кнопка «Новая» внизу;
  - `Chat.tsx` — шапка (пилюля состояния, воркер, путь, модель и стоимость из `usage`,
    «Остановить», меню «Ещё»), лента, плашки подхвата VS Code вместо поля ввода, поле ввода; на
    телефоне открытый запрос — bottom sheet вместо поля ввода;
  - `feed.ts` — чистая логика ленты: группы вызовов инструментов с подписью из промежуточной
    реплики, `usage` под финальным ответом, `tool.call` внутри карточки своего запроса;
  - `cards.tsx` — сообщения, группы инструментов, служебные строки, вопрос агента;
    `permission.tsx` — карточка разрешения (Enter/Esc, ответ текстом, свёрнутая строка);
  - `Workspaces`, `Settings`, `Enroll` — страницы; `Markdown.tsx` — markdown и блоки кода с
    «Копировать»; `icons.tsx` — иконки; `labels.ts` — подписи и форматы.
  `src/clipboard.ts` — копирование через `navigator.clipboard` или скрытый textarea, если API нет
  (http в LAN).
- `public/` — `manifest.webmanifest`, `sw.js`, иконки, `fonts/` — Inter и JetBrains Mono
  (woff2 400/500/600, латиница и кириллица, из `@fontsource/*` 5.3.0, лицензии OFL рядом): хаб
  отдаёт их сам, CSP `font-src 'self'` внешних шрифтов не пускает.
- `mock/` — мок-хаб для разработки и тестов.

Маршруты в hash, чтобы хаб мог раздавать клиент как статику: `#/` — список, `#/s/<id>` —
чат, `#/settings`, `#/enroll?code=ABCD-1234`.

## Мок

`npm run dev:mock` и открыть `http://127.0.0.1:5173`. Мок отдаёт REST и `/api/ws` из §6
(формы, которых нет в спеке, — в `docs/notes/t5-questions.md`) и строит события из
`crates/hqc-proto/examples/wire/*.json`. В нём три сессии: с историей, где есть все виды
карточек (включая неизвестное событие); с недоставленным вводом (кнопка «Повторить»);
пустая. Сценарий хода на любое сообщение: `status running` → `agent.delta` →
`agent.message` (не финальный) → `tool.call`/`tool.result` (Read) → `tool.call` (Bash) →
`approval.request` → ждёт кнопку → `approval.response` → `tool.result` → дельты →
финальный `agent.message` → `usage` → `status idle`. Сообщение со словом «вопрос» или
«clarify» вместо разрешения задаёт `clarify.request`. Ответ текстом на запрос (вариант deny с `message`)
мок принимает и цитирует в финальном ответе. «Стоп» во время хода даёт
`approval.cancel {stopped}`. Сообщение со словом «markdown» или «разметка» получает
потоком ответ со всеми элементами markdown (заголовки, списки с задачами, таблица, код,
ссылки, цитата, HTML и `javascript:`-ссылка текстом) — посмотреть вёрстку глазами. Код регистрации воркера мок принимает в виде `ABCD-1234`.
`MOCK_SPEED=0.3 npm run dev:mock` ускоряет сценарий, `MOCK_PORT` меняет порт мока.

## Проверка на телефоне в локальной сети

1. `HQC_DEV_LAN=1 npm run dev:mock` — **только с моком**. По умолчанию Vite (и мок)
   слушают только `127.0.0.1`: dev-хаб (`HQC_DEV=1`) работает без аутентификации, и Vite,
   открытый в LAN, отдал бы его любому в той же Wi-Fi сети. С `HQC_DEV_LAN=1` Vite слушает
   все интерфейсы и печатает адрес `Network: http://192.168.x.x:5173/`. При первом
   запуске macOS может спросить, разрешить ли `node` входящие соединения, — разрешить.
   С реальным хабом LAN-адрес и не заработает: хаб принимает `Origin` по `http` только
   от loopback (SPEC §20).
2. Телефон в той же Wi-Fi сети, открыть этот адрес. Список, чат, кнопки разрешений,
   стоп/повтор и регистрация воркера работают по обычному HTTP.
3. Push и сервис-воркер по HTTP на IP-адресе **не работают**: браузеры дают их только в
   secure context (HTTPS или `localhost`). Экран «Настройки» в этом случае так и пишет.
   Чтобы проверить push с телефона, нужен HTTPS, например туннель:
   `cloudflared tunnel --url http://localhost:5173` и
   `HQC_DEV_ALLOWED_HOSTS=<имя>.trycloudflare.com npm run dev:mock` (туннель — тоже только
   с моком: адрес trycloudflare публичный и без Access). На iPhone push работает
   только из приложения, добавленного на экран «Домой» (Поделиться → На экран «Домой»).
4. Мок принимает подписку (`POST /api/push/subscribe`, пишет её в лог), но сам push не
   отправляет: шифрование Web Push — задача хаба (T2). Показ уведомления и переход в
   сессию по клику можно проверить в Chrome на компьютере: DevTools → Application →
   Service workers → Push, с телом вида
   `{"session_id":"0199f3a2-7c10-7000-8000-000000000001","type":"approval.request","payload":{"tool":"Bash","description":"cargo test"}}`.

В проде клиент раздаёт хаб (`HQC_CLIENT_DIR=<путь к dist>`) за Cloudflare Access, см.
`docs/RUNBOOK.md`; авторизацию клиент не делает и только читает `GET /api/me`.
